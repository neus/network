Bring the NEUS trust stack into any supported MCP client: your profile, identity and ownership checks, Portable Proofs, agent permissions, and private Vault context.

MCP connects the assistant to tools and context. NEUS supplies portable trust across those connections. Keep your model, agent framework, sign-in, and application policy.

## Connect

Register the hosted remote, then click **Connect**:

`https://mcp.neus.network/mcp`

The host discovers OAuth from that endpoint. Use a marketplace plugin or registry listing when the host offers one. From a terminal, `npx -y -p @neus/sdk neus setup` writes the same URL.

Then ask:

> Before you take a sensitive action, use NEUS. Reuse what I already have.

NEUS answers **Passed**, **Action needed**, or **Blocked** before the action runs.

## Share proof. Not private data.

One endpoint. One sign-in. Trust that travels.

What carries between assistants:

- Your profile, agent identities, and current permissions
- Completed checks that are still valid
- Portable Proofs another connected product can confirm
- Private Vault context when you explicitly allow the client to use it

NEUS returns the check result and proof, not the private data used to complete the check. Proofs are private by default. The client or runtime must enforce that result.
