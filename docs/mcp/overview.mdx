NEUS MCP gives any agent, editor, server, or API the same portable identity, permissions, proofs, context, and Vault. One endpoint. One sign-in. Same authority everywhere.

**Endpoint:** `https://mcp.neus.network/mcp`

### Identity

Verified identity for humans, organizations, and agents. Portable across every connected client.

### Permissions

Scoped authority with spend caps, end dates, and revocation. Checked before tools run.

### Proofs

Reusable verification records. Create once, reuse everywhere. Private by default.

### Context

Portable trusted context that travels with the agent across sessions and environments.

### Vault

Encrypted secrets stored, listed, and revoked through MCP. No keys pasted into chat.

### Gates

Access rules that require current proof before access, payment, or execution.

## Works with any MCP client

Any client that speaks MCP can connect. One endpoint. One sign-in. Same identity, permissions, proofs, and Vault everywhere.

Editors, agent frameworks, chat apps, servers, CI, and custom clients all use the same hosted URL. See [MCP clients](./ide-plugin) for per-client setup.

## How it works

Sign in once. NEUS loads your identity, permissions, and saved proofs.

1. Look up a saved proof before a sensitive action
2. Read proofs and saved context with `neus_proofs_get`
3. Guide any missing verification step
4. Confirm agent identity and authority before tools run
5. Store or revoke Vault secrets when signed in

You see **Passed**, **Action needed**, or **Blocked** in chat. Not raw tool output.

## Agent frameworks

NEUS works alongside your agent framework, not instead of it. Your framework runs the tools. NEUS checks identity and permission before they run.

**Hermes Agent:** Connect NEUS MCP as a tool source. Hermes handles planning, memory, and skill creation. NEUS handles identity, permissions, and proof verification before sensitive actions.

**OpenClaw:** Add the NEUS MCP URL as a remote server. OpenClaw orchestrates channels and subagents. NEUS adds the trust layer that checks who is acting and what they are allowed to do.

**LangGraph, CrewAI, Microsoft Agent Framework:** Any framework that speaks MCP can connect. Your framework handles orchestration and state. NEUS handles the trust layer.

**A2A and EIP-8004:** NEUS publishes per-agent A2A cards and EIP-8004 agent cards for agent-to-agent discovery. Your agents can discover and verify NEUS-registered agents through standard protocols.

**ACP:** NEUS permission proofs complement Agent Communication Protocol. ACP handles inter-agent messaging. NEUS handles the identity and authority layer that says whether a message should be trusted.

## Private cloud agents

Compute is already portable. Frameworks make orchestration portable. Hermes ships six terminal backends. OpenClaw runs on any self-hosted runtime. CrewAI deploys on AWS, Azure, GCP, or on-prem.

The trust state has not been portable. Identity, permissions, and proof history stay trapped in whichever environment the agent was set up in. NEUS fixes that. One identity, one permission set, one proof history, every environment.

**NEUS MCP** is the trust layer. The agent connects from wherever it runs. Identity, permissions, proofs, context, and Vault travel with it.

**The environment** runs the agent and its tools. Optionally, a confidential compute runtime proves the environment itself is genuine — a TEE-attested confidential VM with a hardware quote over the full app hash. [Phala dstack](https://phala.com/dstack) is one such runtime; any TEE that binds the app hash into the quote works the same way. This is an optional hardening layer; NEUS works without it.

NEUS already uses Phala-backed TEE inference for hosted AI. Every hosted model call runs through RedPill's confidential-computing gateway on Phala infrastructure. NEUS verifies the gateway identity, the signed receipt, and the serving path before it shows **TEE verified** in chat.

Full integration guide: [Private cloud agents](../cookbook/private-cloud-agents).

## Quick start

```bash
npx -y -p @neus/sdk neus setup
npx -y -p @neus/sdk neus doctor --live
```

Installs the NEUS skill and configures the MCP endpoint. Click **Connect** in your host or run `neus auth` to sign in. For servers, CI, or automation, use a profile access key.

Per-client setup: [MCP clients](./ide-plugin).
