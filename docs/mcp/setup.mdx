Add a check before your assistant spends, publishes, uses secrets, or calls a sensitive tool. NEUS reuses a current proof when it can and asks only for the missing step.

Register the hosted remote, then click **Connect**. The host discovers OAuth from the endpoint. No wallet or access key is required.

**Hosted endpoint:** `https://mcp.neus.network/mcp`

## Connect

Add this remote server in the host MCP settings, marketplace, or registry:

```json
{
  "mcpServers": {
    "neus": {
      "url": "https://mcp.neus.network/mcp"
    }
  }
}
```

If the host requires the spec `type` field:

```json
{
  "mcpServers": {
    "neus": {
      "type": "http",
      "url": "https://mcp.neus.network/mcp"
    }
  }
}
```

Then click **Connect** and finish browser sign-in.

If the host already offers a NEUS marketplace plugin or registry listing, install that instead of adding a second `neus` entry by hand.

## Protect an action

Ask:

> Before you take a sensitive action, use NEUS. Reuse what I already have.

NEUS answers **Passed**, **Action needed**, or **Blocked** before the action runs.

## Let your assistant run setup

```text
# NEUS connect in one prompt

You are connecting this client to NEUS so it can reuse completed checks
and confirm permission before sensitive actions.

1. Register the hosted MCP remote https://mcp.neus.network/mcp in this
   host (marketplace plugin, registry listing, or URL-only MCP config).
   Do not add a second neus entry.
2. Tell me to click Connect in the host MCP panel if sign-in is not done.
   Do not run neus auth unless this host cannot start sign-in.
3. After connect, reuse my existing proofs before asking me to verify
   again. Before any sensitive action (spend, publish, secrets, agent
   tool call), load context once, then check proofs. Summarize as
   NEUS Verify: Passed, Action needed, or Blocked.

Canonical endpoint: https://mcp.neus.network/mcp
Docs: https://docs.neus.network/mcp/setup
```

## From a terminal

Optional. Writes the same hosted endpoint and the public workflow skill:

```bash
npx -y -p @neus/sdk neus setup
```

If a NEUS plugin is already installed, setup skips a second `neus` entry.

Codex: after the endpoint is registered, run `npx -y -p @neus/sdk neus auth --client codex`. `neus auth --oauth` is only the CLI token store.

## Advanced: connect a Trusted Agent to a project

After creating a Trusted Agent on your profile, load its current identity and permissions:

```bash
npx -y -p @neus/sdk neus mount <agentId> --apply <host>
```

The command writes `.neus/mount.json` and the selected host adapter. See [Connect agent context](../agents/runtime-mount).

## Advanced: access keys

Use OAuth for interactive clients. Use a [profile access key](https://neus.network/profile?tab=account) only when browser OAuth is unavailable, such as a server or CI job.

```bash
export NEUS_ACCESS_KEY=npk_...
npx -y -p @neus/sdk neus setup
```

Treat the key like a password. Never paste it into chat or commit it to a repository.

## Disconnect

```bash
neus disconnect --access-key <token>
```

## Troubleshooting

- **No tools appear:** restart the MCP client after the endpoint is registered.
- **No Connect button, or Unauthorized with Logout visible:** click **Logout**, then **Connect**. Do not run `neus auth` for a host that owns its own sign-in.
- **Two neus servers:** a marketplace plugin and a user MCP config both registered NEUS. Remove the extra `neus` key from the host MCP config. If you used the terminal installer, run `npx -y -p @neus/sdk neus setup` again to drop the leftover user entry.
- **Authentication required:** sign in in the host MCP panel. Codex: `neus auth --client codex`. CLI/doctor only: `neus auth --oauth`.
- **Confirm the connection:** `neus doctor --live` (Node).
- **Agent permission missing:** create or refresh the agent permission on NEUS, then run `neus mount` again.
- **Search-only endpoint:** use `https://mcp.neus.network/mcp`. `https://docs.neus.network/mcp` only searches documentation.

### Cursor

Cursor Local and Cloud are separate sessions. Ignore Cloud unless you want Cloud Agents to use NEUS. Do not run `neus auth` — that writes `~/.neus` and Cursor does not use it. If Local shows **Logout** and **Unauthorized**, click **Logout**, then **Connect**. If both the marketplace plugin and `~/.cursor/mcp.json` registered NEUS, remove the `neus` key from `~/.cursor/mcp.json` or run `npx -y -p @neus/sdk neus setup --client cursor`.
