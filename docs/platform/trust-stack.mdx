Sign-in, gates, saved results, and agent authority share one account. Do not restart from zero in the next product.

## The loop

| Step | What happens |
| ---- | ------------ |
| 1 | Look up a saved result |
| 2 | Run a new check only if needed |
| 3 | Save it on a profile |
| 4 | Reuse before access, payment, or action |

## Building blocks

| Piece | What it is |
| ----- | ---------- |
| **Profile** | Your NEUS account: identity, proofs, agents |
| **Hosted Verify** | Sign-in and checks in the browser (creates or refreshes a proof) |
| **Check** | One trust decision ([catalog](../verification/verifiers)) |
| **Proof** | Portable reusable verification asset (`qHash` in the API) |
| **Portal** | Access surface you publish from Profile → Portals |
| **Gate** | Published policy + checkout ID (`gateId`) you embed; enforced with `gateCheck` |

API paths, MCP tool names, and SDK exports keep their existing identifiers (`/proofs/`, `neus_proofs_*`, `VerifyGate`). Buyer and docs prose use the terms above.
