Connect once. Your assistant carries your identity, trusted context, and scoped authority across editors — reusing what's already verified, enforcing limits before sensitive actions, and leaving a receipt for every result. It reports **Passed**, **Action needed**, or **Blocked**.

## Install

```bash
npx -y -p @neus/sdk neus setup
```

Installs the trust skill, detects Cursor, Claude Code, Codex, and VS Code, and signs you in. One command per editor — no manual MCP config. Your assistant can now check who is acting, what trusted context it carries, and what it's authorized to do before it acts.

Confirm it works:

```bash
npx -y -p @neus/sdk neus doctor --live
```

Then ask your assistant:

```txt
Use NEUS for my identity and what I allow. Reuse saved receipts when you can, verify when you must, and check authority before sensitive actions.
```

More prompts: [MCP journeys](./mcp/journeys).

## Bring your own agent

Already have agents in Cursor, Claude Code, or Claude Desktop? NEUS does not replace them. It adds identity, trusted context, authority, and reusable receipts on top — so every action is provable and auditable.

**Import existing IDE config:**

```bash
neus import --from auto
```

Detects Cursor, Claude Code, and Claude Desktop workspaces and snapshots their config into a portable NEUS manifest. Use `--from cursor`, `--from claude-code`, or `--from claude-desktop` to target one.

**Connect a registered agent to a project:**

```bash
neus mount <agentId> --apply cursor
```

Writes `.neus/mount.json` with the agent's verified identity, permissions, and host rules. Run it again after permission changes. See [Connect agent context](./agents/runtime-mount).

**Agent frameworks:** Any agent that can sign with a wallet or complete a hosted step works the same way: identity for who they are, authority for what they may do. Results travel across runtimes. See [Agent verification flow](./agents/agent-verification-flow).
